# rza1-pac

Register access for the Renesas RZ/A1L and RZ/A1H, generated by [chiptool] from the vendor SVD
(`vendor/rza1.svd`). Enable exactly one chip feature: `rza1l` (the RZ/A1L, R7S72102x) or `rza1h`
(the RZ/A1H, R7S72100x). Every peripheral is a `Copy` handle (`CPG`, `SCIF0`, `INTC`, …) whose
methods return register handles.

The vendor SVD describes the RZ/A1H. The `rza1l` PAC is that SVD minus what the RZ/A1L lacks, plus
registers it has that the SVD omits. The deletions, `transforms/rza1l/absent.yaml`, are generated
by `tools/pac-a1l-absent.py` from the RZ/A1L manual's register list (Table 46.1, R01UH0437EJ0700),
and `tools/pac-check-a1l.py` checks the generated RZ/A1L PAC against that list both ways: every
register it defines is an RZ/A1L register at an allowed width, and every RZ/A1L register is in it,
apart from named exceptions.

Do not edit `src/chips/*.rs` or `transforms/rza1l/absent.yaml`: change the other transforms and run
`tools/gen-pac.sh`. `tools/test.sh` runs `tools/gen-pac.sh --check`, which fails on drift or a
mismatch with the manual.

The generated code uses this crate's own `common::Reg` (chiptool's `--common-module`), which sends
every read and write through `mmio`: real volatile accesses on the device, a shadow memory with an
access log under host tests, so drivers' register sequences can be tested.

[chiptool]: https://github.com/embassy-rs/chiptool
